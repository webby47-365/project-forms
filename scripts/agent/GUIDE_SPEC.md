# 정보형 가이드 작성 규칙 (정본)

`guides/<slug>.yaml` 1개 = 가이드 1편 = `/guide/<slug>/` 1페이지.
검사는 `scripts/guides.py` 의 `check_guide()` 가 하고, `validate_catalog.py` 가 위반을 **배포 중단 오류**로 처리한다.
이 문서의 숫자를 바꾸면 `guides.py` 상단 상수도 같이 바꾼다.

## 1. 가이드가 맡는 검색어

서식 상세는 "사직서 양식"처럼 **내려받으려는** 검색을 받는다. 가이드는 그 앞 단계,
"사직서 제출 후 퇴사 절차", "연차수당 계산법", "전세 계약 전 확인사항"처럼 **알아보려는** 검색을 받는다.

좋은 주제의 조건 (셋 다 만족):

1. 20~30대 직장인·자취생이 실제로 검색하는 **절차·기준·계산법** 질문이다
2. 우리 서식 **2~4종**을 자연스럽게 이어 쓸 수 있다 (가이드를 읽고 → 서식을 받는다)
3. 법령·기관 자료로 **1차 출처를 댈 수 있다**

만들지 않는 것: 서식 한 종의 작성법만 되풀이하는 글(서식 상세의 howto 와 중복), 뉴스성 글(금방 낡음),
투자·질병 치료처럼 우리 서식과 무관한 주제, 특정 기업·기관 비방.

## 2. 파일 형식

```yaml
slug: annual-leave-pay            # 영문 소문자·숫자·하이픈. 파일명과 같게
status: draft                     # draft(검수 전·비공개) → 사람이 검수 후 published. 내릴 때는 retired
group: pay                        # quit | pay | contract | housing | life | career | money
title: 연차 발생 기준과 연차수당 계산법          # 40자 이내. 검색어를 앞쪽에
description: 70~160자. 검색 결과 설명문. 무엇을 알 수 있는지 구체적으로.
summary: 80~260자. '핵심 요약' 상자와 AI 검색 인용용 결론. 숫자·기준을 직접 적는다. **굵게** 가능
keywords: [3~10개]
created_at: 2026-09-15
updated_at: 2026-09-15            # 내용을 고치면 갱신 (사이트맵 lastmod 가 된다)
basis_date: 2026-09-15            # 필수. 법령·요율을 확인한 기준일 → 글 상단 "○○ 법령·요율 기준". 값을 다시 확인하면 갱신
show_on: [leave-request, /tools/annual-leave/]   # 선택. 서식 상세·계산기의 '쓰기 전에 읽어 보세요' 카드에 이 글을 띄울 곳
                                  #   서식 id 또는 도구 경로 1~8개. 비우면 forms + tools 에 자동으로 뜬다
sections:                         # 4~9개
  - h: 1. 소제목
    body: |                       # 문단은 빈 줄로 나눈다
      본문. **굵게**, [내부 링크](/form/leave-request/) 만 허용. 외부 링크는 sources 에만.
    list: [선택]                   # 글머리표 목록
    table:                        # 선택. head 칸 수 = 각 row 칸 수
      head: [항목, 값]
      rows:
        - [시간당 통상임금, "3,000,000 ÷ 209 = 14,354원"]   # 쉼표가 들어가면 반드시 따옴표
forms: [leave-request, annual-leave-plan]   # 2~4개. catalog.json 에 있는 id
tools: [/tools/annual-leave/]               # 선택. build_site.TOOLS 의 경로
faq:                                        # 2~5개. 평문 (굵게·링크 쓰지 않음)
  - q: 질문
    a: 답
sources:                                    # 1개 이상. https 로 시작
  - name: 국가법령정보센터 — 근로기준법 제60조
    url: https://www.law.go.kr/법령/근로기준법
```

## 3. 분량과 구성

- 섹션 본문(문단+목록+표) 합계 **공백 제외 1,500자 이상** — 미만이면 오류 (목표 1,500~2,500자)
- 섹션 순서는 **독자가 일을 처리하는 순서**로 (확인 → 준비 → 작성 → 제출 → 사후)
- 첫 섹션 첫 문단에서 질문에 대한 답을 먼저 준다. 배경 설명으로 시작하지 않는다
- 표는 '조건별로 달라지는 값'에만 쓴다 (예: 근속별 연차 일수, 상황별 효력 발생일)
- 본문 중간에 연결 서식·도구를 **링크로 1회 이상** 걸어 흐름 속에서 이동하게 한다
- 서식 상세의 howto·faq 문장을 복사하지 않는다. 연결 서식의 작성 순서는 템플릿이 자동으로 붙인다

## 4. 정확성 (가장 중요)

가이드는 법·돈 이야기라 틀리면 사이트 신뢰가 무너진다.

1. **숫자·기한·요율·조문 번호는 1차 출처에서 확인한 것만 쓴다.** 국가법령정보센터(law.go.kr),
   고용노동부(moel.go.kr), 국세청(nts.go.kr), 찾기쉬운 생활법령정보(easylaw.go.kr),
   공단(nps·nhis·comwel), 법원(scourt.go.kr). 블로그·계산기 사이트 숫자는 근거로 쓰지 않는다
2. 확인한 출처를 `sources` 에 적는다. 출처를 댈 수 없는 숫자는 문장에서 뺀다.
   **`pay`·`money` 그룹은 기관 도메인(go.kr·or.kr) 출처가 1건 이상 없으면 오류**다
3. 해마다 바뀌는 값(최저임금·보험요율·기준금액)은 **연도를 함께 적는다** ("2026년 최저임금은 …")
4. 과태료·벌금 액수처럼 개정이 잦고 출처끼리 엇갈리는 값은 액수를 쓰지 말고 "과태료가 부과될 수 있다"로 쓴다
5. 단정적인 법률 판단("무조건 이긴다", "반드시 무효")을 쓰지 않는다. "~할 수 있습니다", "~로 보는 것이 일반적입니다"
6. 계산 예시는 **직접 계산해서** 검산한다 (`python -c` 로 확인)

## 4-1. 주제 범위 (그룹)

| 그룹 | 다루는 것 | 다루지 않는 것 |
|---|---|---|
| quit 퇴사·이직 / pay 급여·근로 | 퇴사 절차, 실업급여, 권고사직·해고, 연차, 괴롭힘, 근로계약 | 특정 회사 사례 비방 |
| career 커리어 | 이력서·경력기술서·자기소개서, 이직 준비, 면접 | 합격 보장식 과장 |
| money 세금·재테크 | **세테크·연말정산·카드 소득공제만** | 부업·N잡, ETF·코인·주식, 대출 금리 — 사이트에 쓰지 않는다(YMYL·정체성 불일치) |

## 4-2. 카드 노출 (서식 상세·계산기)

- 서식 상세는 FAQ 바로 뒤, 계산기는 개인정보 안내 아래에 **'쓰기 전에 읽어 보세요' 상자**가 붙고 글은 **최대 2편**이다
- `show_on` 에 그 서식·도구를 적은 글이 먼저, 그다음 `forms`·`tools` 로 연결된 글이 최신순으로 채운다
- 한 서식에 3편 이상이 몰리면 가장 가까운 2편만 `show_on` 에 남긴다

## 5. 검증

```bash
python scripts/build_site.py        # 규칙 위반 가이드는 "[사이트] 알림: [가이드] …" 로 찍히고 빠진다
python scripts/validate_catalog.py  # 같은 위반이 [오류] 로 나오면 배포 불가 → 고친다
```

생성된 `public/guide/<slug>/index.html` 을 열어 표가 깨지지 않았는지, 링크가 살아 있는지 확인한다.

## 5-1. 생산·검수 (애드센스 심사 기준)

- **일일 에이전트는 `status: draft` 로만 쓴다.** draft 는 검사기를 통과해야 커밋되지만 사이트에는 나오지 않는다
- 사람(또는 검수 세션)이 숫자·출처·연결 서식을 확인한 뒤 `published` 로 바꾸고 `updated_at` 을 갱신한다. 주 2~3편
- 애드센스 승인 전 공개 가이드는 **15편 이하**로 유지한다

## 6. 수정·내리기

- 내용 수정: 본문을 고치고 `updated_at` 갱신
- 내리기: `status: retired` (파일은 남긴다). 다음 빌드에서 페이지·사이트맵·서식 상세의 링크가 함께 빠진다
- slug 는 바꾸지 않는다 (주소가 바뀌어 쌓인 검색 노출이 사라진다)
