# 네이버 블로그 초안 에이전트 지침 (정본) — "각종서식 작성하기"

서식 1종 = **네이버 블로그 초안 1편**을 `C:\Project_Forms\Claude outputs\blog\YYYY-MM-DD_<서식id>\` 에 넣는다 (날짜 = 발행 예정일).

## 0-0. 실행 방식 — "켜져 있으면 3일치 유지"

- 컴퓨터에 연결된 예약 작업이 **07:00~23:00 KST 매시간** 깨어난다. 컴퓨터가 꺼져 있으면 그 회차는 건너뛰고, 켜진 뒤 다음 정각에 작업한다
- **목표: 오늘·내일·모레(오늘 포함 3일) 날짜의 초안 폴더가 모두 있는 상태**
  1. `device_list_dir` 로 `Claude outputs\blog\` 의 `YYYY-MM-DD_*` 폴더를 본다 (폴더 안에 `post.html` 이 있어야 완성본으로 친다)
  2. 오늘~모레 3개 날짜가 모두 있으면 **아무것도 하지 않고 즉시 종료** (사용량을 쓰지 않는다)
  3. 빠진 날짜를 **가까운 날부터** 채운다. 한 회차에 최대 3편
  4. 지난 날짜의 폴더는 건드리지 않는다(사람이 발행했거나 보관 중)
- 이미 있는 날짜의 초안은 다시 만들지 않는다. 고칠 일이 있으면 사람이 요청한다
게시는 사람이 한다(복사·붙여넣기 후 편집). 이 폴더는 `.gitignore` 대상이라 GitHub(공개 저장소)에 올라가지 않는다 —
**블로그 원문이 웹에 먼저 공개되면 네이버가 블로그 글을 유사문서로 볼 수 있으므로 절대 커밋하지 않는다.**

## 0. 산출물 (폴더 1개 = 글 1편)

| 파일 | 내용 |
|---|---|
| `post.json` | 글 원본(블록·사진 명세). 빌더 입력 |
| `post.html` | 브라우저로 여는 초안. 왼쪽 본문(인라인 스타일 — 굵게·색·밑줄·글자 크기·표·링크), 오른쪽 [본문 복사]·[제목 복사]·[태그 복사], 발행 정보, 사진 순서, 발행 전 체크 |
| `01_대표이미지.png` | 1080×1080 썸네일(홈피드·검색 목록에 보이는 첫 사진) |
| `02_작성예시_번호.png` | 사이트 예시 미리보기에 번호 원·강조 테두리 |
| `03_…png` | 비교 카드(틀린 예/바른 예) 또는 표·흐름 카드 — 서식에 맞게 1장 |
| `04_…png` | 체크리스트 카드 |

**만드는 법**: `post.json` 을 쓰고 `python scripts/blog/build_blog_post.py <폴더>` 를 실행하면 사진 PNG 와 `post.html` 이 생긴다.
빌더가 규칙(글자 수 1,800~2,500·제목 25~40자·태그 8~10·링크 1개 맨 끝·UTM·사진 자리 수·첫 블록 대표 사진·요약 상자·경험 문단 id `exp`·상투 문장)을 검사하고,
위반이 있으면 파일을 만들지 않는다 — 고칠 때까지 반복한다. 서식 미리보기는 폴더에 `_preview.webp` 로 복사해 둔다.

본문의 사진 자리는 `[사진 넣기] 파일명` 줄로 표시한다. 스마트에디터는 붙여넣은 HTML 속 로컬 이미지를 올리지 못하므로
사진은 사람이 그 자리에 끌어다 넣는다. 이미지 생성은 `scripts/blog/blog_images.py`(thumbnail·annotate·compare·checklist).

## 1. 서식 선정 — 검색 수요 순서

1. `Claude outputs\blog\_queue.json` 의 `order` 에서 `done` 에 없는 첫 서식을 고른다
2. 단, `python scripts/season.py` 가 **선행 구간(+20)** 시즌을 내면, 그 시즌 키워드에 맞는 서식이 큐 30위 안에 있을 때 앞당긴다
3. 같은 계열(series)은 연속 2일 쓰지 않는다
4. 쓴 뒤 `done` 에 `{id, date, title}` 를 추가한다

큐 순서는 검색량 추정(서식명 단독 검색 수요가 큰 순)이다. 사용자가 네이버 검색광고 키워드 도구의 월간 검색수 CSV를
`Claude outputs\blog\keywords.csv` 로 넣어 두면 그 수치로 다시 정렬한다.

## 2. 네이버 노출 원칙 (2026-09-15 조사 — 공식 확인과 업계 관찰을 구분)

**공식·보도로 확인된 구조**
- 네이버 앱 **홈피드**(2023-11 도입)는 이용자가 본 블로그·검색 기록 등으로 개인화 추천하며, 카드에는 **대표 이미지와 제목**이 보인다
- 2026년 네이버는 연관검색어를 없애고 **AI 브리핑**(블로그·카페 등을 요약 인용)을 확대했다 — 질문에 바로 답하는 문단·표·목록이 인용되기 쉽다
- 검색 순위는 출처 신뢰(C-Rank)와 문서 품질(D.I.A.) 계열 평가를 쓰며, 고정된 글자 수·게시물 수·금칙어 기준은 공개된 적 없다

**업계 관찰(비공식) — 따르되 과신하지 않는다**
- 체류 시간·클릭률·반응(공감·댓글)이 홈피드 노출과 함께 움직인다
- 같은 문장 복붙·키워드 반복·짧은 글 연속·몰아서 발행·광고성 외부 링크 과다가 저품질과 함께 관찰된다
- AI 글 자체보다 **상투적 도입("오늘은 ~에 대해 알아보겠습니다")·채우기 문장·경험 없음·팩트 오류**가 문제로 지목된다

## 4. 절차 (예약 작업 1회차)

작업은 클라우드 작업공간에서 하고, 결과만 컴퓨터 폴더로 보낸다.

1. **확인** — `device_list_dir C:\Project_Forms\Claude outputs\blog` → 오늘~모레(KST) 3개 날짜 폴더에 `post.html` 이 다 있으면 즉시 종료
2. **가져오기** — `device_stage_files` 로 `Claude outputs\blog\_queue.json`, `catalog\catalog.json`,
   `scripts\blog\blog_images.py`, `scripts\blog\build_blog_post.py`, `scripts\agent\blog_draft_agent.md`(이 문서), 필요 시 `scripts\season.py`·`catalog\season_calendar.json` 을 가져온다
3. **빈 날짜마다** (가까운 날부터)
   1. 서식 선정(1절) → 그 서식의 `public\files\<id>\preview-1.webp` 를 가져와 폴더에 `_preview.webp` 로 둔다
   2. 미리보기를 **직접 열어 보고** 번호 표시 좌표(annotate markers)를 정한다
   3. 필요한 사실은 1차 출처로 확인, 못 찾은 숫자는 쓰지 않는다
   4. `post.json` 작성 → `python build_blog_post.py <폴더>` → 위반 0건까지 수정
   5. 만든 사진 4장을 직접 열어 글자 잘림·번호 위치 확인
   6. `_queue.json` 의 `done` 에 `{id, date, title, category}` 추가
4. **보내기** — 폴더 전체(post.json·post.html·PNG, `_preview.webp` 제외)와 `_queue.json` 을 `device_commit_files` 로 이관.
   **같은 임시 경로를 두 번 쓰지 않는다**(예전 내용이 다시 써지는 도구 함정) — 회차마다 새 경로에서 보낸다
5. **보고** — 만든 날짜·서식·카테고리를 한 줄씩 남긴다. 컴퓨터 연결이 끊겨 보내지 못했으면 그 사실만 남기고 끝낸다(다음 회차가 다시 만든다)
