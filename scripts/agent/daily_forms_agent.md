# 일일 서식 추가 에이전트 운영 지침 (정본)

이 문서는 매일 08:00(KST) 실행되는 Claude 스케줄 작업의 **지침 정본**이다.
스케줄 작업의 프롬프트는 "저장소의 `scripts/agent/daily_forms_agent.md`를 읽고 그대로 수행하라"로
짧게 두고, 절차 변경은 이 문서만 고친다.

## 0. 전제

- 저장소: `C:\Project_Forms`(로컬 정본) ↔ GitHub `main` ↔ Cloudflare Pages 자동 배포
- 실행 환경: Claude 클라우드 세션(매 실행 새 세션). 로컬 PC가 꺼져 있어도 동작해야 한다.
- 하루 상한: **신규 서식 3종**, 주간 상한 15종
- 승인 채널: 텔레그램 (매매봇 알림과 **다른 봇 토큰** 사용)
- 토큰·키는 스케줄 작업의 환경 비밀변수에만 두고, 이 문서와 저장소에 절대 기재하지 않는다

## 1. 환경 준비 (매 실행 첫 단계)

```bash
pip install python-docx python-hwpx jinja2 pyyaml pillow --break-system-packages -q
# LibreOffice·poppler(pdftoppm·pdfinfo·pdftotext)가 없으면 설치
```

한글 폰트 대체 설정(맑은 고딕 → Noto Sans CJK KR)을 `~/.config/fontconfig/fonts.conf`에
넣고 `fc-cache -f`를 실행한다. 이 설정이 없으면 PDF·미리보기에서 한글이 깨진다.

저장소를 클론하고 작업 폴더로 이동한 뒤, 다음 문서를 **반드시 먼저 읽는다**.

1. `scripts/SPEC_GUIDE.md` — 명세 작성 규칙
2. `catalog/categories.json` — 유효한 분류 키
3. `catalog/catalog.json` — 이미 있는 서식 목록 (중복 방지)

## 2. 수요 조사 (08:00~08:10)

웹 검색으로 다음 신호를 모은다.

- **검색 수요**: "○○ 서식", "○○ 양식 다운로드" 류 검색어와 연관검색어
- **시기성**: 아래 캘린더를 우선 반영
  | 시기 | 수요가 오르는 서식 |
  |---|---|
  | 1~2월 | 연말정산 관련 동의서·위임장, 근로소득 관련 |
  | 2~3월 | 이사(임대차·전입), 신학기(학교 제출 서류) |
  | 3~4월 | 채용 시즌(이력서·경력기술서), 주주총회·정관 |
  | 5월 | 종합소득세 관련 위임·확인서 |
  | 7~8월 | 휴가·하계 행사, 이사 성수기 |
  | 9월 | 신학기, 추석 거래·정산 |
  | 11~12월 | 연말 정산 준비, 인사발령·평가, 계약 갱신 |
- **커뮤니티 신호**: 취업·법률·부동산·소상공인 커뮤니티의 "양식 어디서 구하나" 류 질문
- **자체 검색 로그**: (통계 연동 후) 사이트 검색어 중 결과가 없었던 검색어 — 가장 강한 신호

## 3. 후보 선정

기존 카탈로그의 `title`·`tags`와 겹치는 후보는 제외한다. 남은 후보를 다음 기준으로 점수화하여
상위 5건을 고른다.

| 항목 | 배점 | 판단 기준 |
|---|---|---|
| 수요 | 40 | 검색량·질문 빈도 |
| 시기성 | 20 | 위 캘린더 부합도 |
| 카테고리 공백 보완 | 20 | 서식이 0~2종인 중분류를 채우는지 |
| 제작 난도(역산) | 20 | 블록 조합으로 정확히 만들 수 있는지 |

**현재 비어 있는 중분류를 우선한다** (실행 시점의 카탈로그로 재확인):
기업·영업·마케팅, 기업·창업·법인, 법률·소송·민원, 의료·복지·동의·신청.

## 4. 승인 요청 (08:10까지)

텔레그램으로 아래 형식으로 전송한다.

```
[무료서식] 오늘 추가 후보 (2026-00-00)
1) 거래처등록신청서 — 기업·영업·마케팅 (해당 분류 0종, 소상공인 수요)
2) 상가임대차계약서 — 부동산·임대·매매 (이사철, 주택용만 있음)
3) 지급명령신청서 — 법률·소송·민원 (해당 분류 0종)
4) 반성문 — 법률·소송·민원 (검색 수요 지속)
5) 진료 동의서 — 의료·복지 (해당 분류 0종)

번호로 답장하세요 (최대 3개, 예: 1,3). 0 = 오늘 생성 없음.
```

**무응답 정책**: 12:00까지 응답이 없으면 **당일 생성을 하지 않는다.** 후보는 다음 날 재상정한다.
(승인 없이 생성·게시하지 않는다. 이 정책은 2주 시범운영 후 재검토한다.)

## 5. 생성

승인된 서식마다 다음을 수행한다.

1. `specs/{id}.yaml` 작성 — `SPEC_GUIDE.md`의 블록 문법을 정확히 따른다.
   `id`는 영문 소문자·하이픈, 파일명과 일치. `featured: false`.
   - **미리보기 예시값(sample)** 은 3-1절 규칙대로 반드시 넣는다.
   - **상세 화면 본문 `howto`·`faq`** 도 3-2절 규칙대로 반드시 넣는다
     (howto 3~5단계·각 60자 이내, faq 2~4문항·질문 34자 이내). 계열 서식이면 `variant_use`까지.
     이 세 가지가 체류시간과 검색 유입을 만드는 부분이라 빠뜨리면 페이지가 비어 보인다.
2. `python scripts/check_spec.py {id}` — **[통과]** 가 나올 때까지 수정한다.
3. `python scripts/build_form.py {id}` — 다음을 확인한다.
   - `[완료] 1p` (목표 페이지 이내)
   - `[경고]` 가 있으면 원인을 해결한다 (항목 누락·개인정보·파일 크기)
   - 목표 페이지를 넘기면 `python scripts/fit_one_page.py {id}` 로 보정한다
4. 생성된 `public/files/{id}/preview-1.webp` 를 **직접 열어 눈으로 확인한다.**
   표가 깨졌거나 칸이 비정상적으로 크면 명세를 수정하고 다시 빌드한다.

## 6. 검증·배포

```bash
python scripts/build_site.py
python scripts/validate_catalog.py     # 오류 0건이어야 한다
git add -A
git commit -m "feat(forms): add {id1},{id2} [agent]"
git push
```

푸시 후 Cloudflare Pages 배포가 끝나기까지 약 1~2분 기다린 뒤 다음을 확인한다.

- `https://<사이트>/form/{id}/` 가 200
- `.pdf` `.docx` `.hwpx` 3개 파일이 모두 200

## 7. 리포트

텔레그램으로 전송하고, 동일 내용을 `logs/YYYY-MM-DD.md`에 저장한 뒤 커밋한다.

```
[무료서식 일일 리포트] 2026-00-00 (목) 08:42 KST
승인: 2/5  생성: 2  실패: 0  배포: 완료(1분 40초)
 1) 거래처등록신청서 (기업·영업·마케팅)  /form/vendor-registration/
 2) 상가임대차계약서 (부동산·임대·매매)  /form/commercial-lease-contract/
다음날 재검토 후보: 지급명령신청서, 반성문, 진료 동의서
카탈로그 합계: 48종 / 배포 파일: 284개
```

매주 월요일에는 리포트에 다음을 추가한다.

- 카테고리별 서식 수와 비어 있는 중분류
- (통계 연동 후) 주간 인기 서식 상위 10종과 결과 없는 검색어
- 대표 서식 10종 교체 제안 (다운로드 순위 기준)

## 8. 안전장치 (반드시 지킬 것)

- **생성 상한**: 하루 3종, 주 15종을 넘기지 않는다.
- **승인 없는 게시 금지**: 승인받지 않은 서식을 `status: published`로 올리지 않는다.
- **저작권**: 특정 기업·기관의 등록 서식을 복제하지 않는다. 상용 서식 사이트의 파일을
  가져오지 않는다. 법정 서식은 법령 별지 서식을 참고하고 `source: law-standard`와
  `source_note`에 근거 법령을 적는다.
- **개인정보**: 주민등록번호 항목을 만들지 않는다(빌드 검수에서 차단됨). 건강·병력·종교·
  정치성향 등 민감정보 기재란을 새로 만들지 않는다.
- **법률 판단 금지**: 서식 틀만 제공한다. 본문에 단정적인 법률·세무 판단을 쓰지 않고,
  필요하면 `notice`로 "제출처·법령 기준을 확인하십시오" 수준으로 안내한다.
- **비밀정보**: 토큰·키를 커밋 내용·리포트·로그에 남기지 않는다.
- **롤백**: 문제 서식이 발견되면 명세의 `status`를 `retired`로 바꾸고 재빌드·재배포한다.
  파일은 남기고 노출만 중단된다.
- **분기 점검**: 매 분기 첫 실행 시 `source: law-standard` 서식의 근거 법령 개정 여부를
  점검하고, 개정이 있으면 리포트에 보고한다.

## 9. 실패 시 처리

- 생성 실패: 1회 재시도한다. 재실패하면 해당 서식을 건너뛰고 사유를 리포트에 적고,
  다음 날 후보로 재상정한다.
- 검증 실패(`validate_catalog.py` 오류): **커밋하지 않는다.** 원인을 리포트하고 종료한다.
- 배포 확인 실패: 커밋은 유지하고 리포트에 "배포 확인 실패"로 남긴다. 다음 실행 시 재확인한다.
- 텔레그램 전송 실패: 로그 파일에는 반드시 남기고, 다음 실행의 리포트에 이어서 보고한다.

## 10. 로컬 정본 동기화

에이전트는 클라우드에서 GitHub에 직접 커밋한다. 관리자가 로컬에서
`.\deploy_forms.ps1 -Pull` 을 실행하면 그 결과가 로컬 정본(`C:\Project_Forms`)에 반영된다.
**최종 정본은 항상 로컬**이라는 원칙을 유지하기 위해, 리포트 말미에
"로컬 동기화 필요: `.\deploy_forms.ps1 -Pull`" 한 줄을 항상 포함한다.
