## 2. B라인(2차분) 작업지시서

### 2-1. 목표
모바일 상세 페이지에서 **다운로드까지의 거리**를 줄이고, 계열 비교표·미리보기·버튼 크기 등 "받기" 동선의 마찰을 없앤다. 대상 5건: B-1, B-4, C-8, C-10, C-13.

### 2-2. 사전 조사 (클로드코드가 먼저 할 일)
1. 상세 템플릿 파일명 확인 (`templates/form.html` 또는 `detail.html`) 과 `.detail` 그리드 구조(왼쪽 미리보기 열 / 오른쪽 정보·다운로드 열)를 파악한다. 현재 `@media (max-width:1000px){ .detail{grid-template-columns:1fr} }` 로 1열이 될 때 DOM 순서대로 쌓여 미리보기가 먼저 나온다.
2. 계열 허브 템플릿(`templates/series.html`)의 `.cmp-wrap > table` 구조와 열 구성(버전 / 이럴 때 쓰세요 / 분량 / 받기 3버튼)을 파악한다.
3. 카드 파셜(`_card.html` 등)에서 `.dl a` 3버튼의 마크업을 확인한다.

### 2-3. 항목별 요구사항

**B-1. 모바일 상세 순서 재배치 (1000px 이하)**
- 목표 순서: 빵부스러기 → **h1 제목 + 한 줄 요약** → **다운로드 3버튼(PDF·Word·한글)** → 미리보기 이미지 → 도장 위젯 → 정보표(분류·페이지·형식…) → 작성 순서 → 항목 텍스트 → FAQ → 연관 서식 → 모음.
- 구현 방식은 CSS `order`(권장) 또는 템플릿에서 모바일 전용 블록 복제 중 택1. 복제 시 다운로드 버튼이 페이지에 두 번 생기므로 **GA4 이벤트 중복 집계가 없는지**(`data-no-track` 규칙과 충돌 없는지) 확인한다.
- 미리보기가 2페이지 이상이면 모바일에서는 **첫 페이지만 보이고 "2페이지 더 보기" 버튼으로 펼침**(높이 절감). PC는 변경 없음.
- PC(1000px 초과)는 현재 배치를 그대로 둔다. 단 **C-8의 sticky 패널**은 PC에만 적용.

**B-4. 계열 비교표 모바일 대응 (720px 이하)**
- 표를 그대로 두고 오른쪽이 잘리는 현재 상태를 없앤다. 권장: 720px 이하에서 `<table>` 을 숨기고 같은 데이터로 **카드 리스트**(버전명 굵게 / 한 줄 설명 / 분량 / PDF·Word·한글 3버튼)를 렌더링. 템플릿에서 같은 반복문으로 두 마크업을 출력하고 CSS로 폭에 따라 하나만 보이게 한다.
- 대안(간단): `.cmp-wrap` 오른쪽 끝에 그라데이션 마스크 + 표 위에 "옆으로 밀어 보세요 →" 안내 한 줄. 카드형이 어렵다면 이 방식으로.
- 표 안의 버튼도 C-10 크기 규칙을 따른다.

**C-8. 미리보기 확대 + PC 패널 고정**
- 상세 미리보기 `<img>`를 `<button>`/`<a>`로 감싸 탭하면 **전체화면 라이트박스**(어두운 배경, 원본 800px 이미지, 핀치 줌 가능하도록 `touch-action: pinch-zoom`, ✕ 버튼과 배경 탭·Esc로 닫기). 외부 라이브러리 없이 20~30줄 JS.
- 이미지에 `cursor: zoom-in`, 아래에 작은 안내 "탭하면 크게 보기".
- PC(1000px 초과): 오른쪽 정보·다운로드 열을 `position: sticky; top: 78px` 로 고정해 긴 미리보기를 읽는 동안 다운로드 버튼이 보이게 한다. 열 높이가 화면보다 크면 A-3과 같은 `max-height: calc(100vh - 94px); overflow-y: auto` 규칙 적용.

**C-10. 카드 다운로드 버튼 터치 크기**
- 720px 이하에서 `.dl a` 높이 **40px 이상**, 버튼 간격 8px, 글자 14px 유지. PC는 현재 33px 그대로.

**C-13. HWPX 안내**
- 카드·상세의 "한글" 버튼에 `title="HWPX (한글 2014 이상)"` 추가.
- 상세 다운로드 패널 아래 보조문구 한 줄: "한글 파일은 HWPX 형식입니다 — 한글 2014 이상에서 열립니다." (12.5px, muted 색).

## 4. 개발 경험치 (개발가이드 반영 후보)
- 클로드 내장 브라우저 창이 좁을 때(≈574px) 넓은 뷰포트 에뮬레이션 캡처가 깨진다. 이 경우 캡처 대신 DOM 치수 검사(JS)로 판정하고, 시각 확인은 클로드코드의 Edge 헤드리스 캡처를 쓴다.
- 클로드코드에 UI 수정을 맡길 때는 ① 보고서 파일을 저장소 `docs\`에 넣고 ② 항목 번호로 지시하며 ③ "배포 금지, 로컬 빌드 + before/after 캡처"를 명시하면 검증 가능한 결과물이 나온다.
- sticky 요소는 항상 `max-height: calc(100vh - top - 여백)` + `overflow-y:auto` 를 함께 준다(사이드바·메뉴 패널 모두 같은 결함이었다).
- 검색 입력은 JS keydown 대신 `<form method="get">` 을 기본으로 — 돋보기 버튼·모바일 키보드 '검색' 키·JS 없는 환경이 한 번에 해결된다.
