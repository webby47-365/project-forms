### WS4. 네이버 공식 블로그 (유입 — 국내 최대 통로)

- **왜**: 네이버는 "사직서 양식"에 자체 서비스와 블로그 탭을 웹문서보다 위에 놓는다. 외부 사이트는 블로그 탭을 통해서만 네이버 유입을 만들 수 있다.
- **원칙**: 글의 정본은 사이트(WS2·WS3), 블로그는 **60% 분량으로 다시 쓴 요약본 + 미리보기 이미지·계산기 캡처 + 링크(UTM)**. 같은 문장을 복사하면 유사문서로 묶여 노출이 떨어진다.
- **주제 범위**: ①②③ 전부 가능. 부업·투자 글은 여기에만
- **게시 방식** (미결정 — 9절): (a) 에이전트가 초안·이미지를 `Claude outputs\blog\` 에 만들어 두고 사용자가 하루 5분 붙여넣기 (b) 내장 브라우저 자동화로 게시. 네이버 블로그는 글쓰기 API가 없다
- **시작 시점**: 사이트 가이드 10편 라이브 뒤(10월 첫째 주). 주 3~5편
- **준비물** [사용자]: 네이버 계정·블로그 개설(블로그명·프로필 이미지), 사이트 하단에 블로그 링크
- **완료 기준**: 첫 10편 게시 · GA4 referral 에 naver 블로그 유입 집계

### WS6. 공유 엔진·쉬어가는 코너 (유입 — 바이럴)

- **승인 후**: 쉬어가는 코너 기획서대로 `play.freeforms.kr` — 테스트류(퇴사 유형 `resign`) → 추리 → 방탈출. 진입점은 다운로드 이후 지점에만

## 8. 품질·검수 기준

1. **얇은 페이지 금지** — 가이드 본문 1,200자(공백 제외) 이상은 검사기가 막는다. 연봉 페이지는 표·설명·FAQ가 있어 통과하지만 30일 노출 0 페이지가 30% 를 넘으면 조정
2. **YMYL 주의** — 금융·법률 글은 기관 출처 1건 이상, 기준일 표시, 면책 고지. 투자·대출 글은 사이트에 넣지 않는다
3. **중복 금지** — 서식 howto·faq 문장 재사용 금지, 블로그본은 문장을 새로 쓴다
4. **기계가 읽는 산출물은 파서로 검증** — 가이드 JSON-LD(Article)도 `validate_catalog.py` 의 JSON 파싱 검사에 포함
5. **사람 검수** — 에이전트 가이드는 매주 월요일 사후 검수. 위반은 `status: retired`
6. **UI 변경은 비교 이미지 먼저** — C안도 실제 서식 3종으로 라이브 전 캡처 확인

## 12. 개발가이드 반영 필요 항목

1. **콘텐츠 사이트의 유입은 "페이지 수 × 검색 의도 종류"로 설계한다.** 거래형(다운로드)·정보형(가이드)·수치형(금액별 페이지)을 나누어 각각 착지 페이지를 두고 서로 연결한다.
2. **국내 검색은 네이버 블로그 탭이 별도 통로다.** 외부 사이트는 웹문서로 이기지 못하므로 요약본+링크 전략을 처음부터 계획에 넣는다.
3. **정본은 한 곳, 파생본은 다시 쓴다.** 사이트 글을 그대로 복사한 블로그 글은 유사문서로 묶인다.
4. **금융·법률(YMYL) 글은 자동 생산의 예외 영역.** 기준일·기관 출처·면책 고지를 명세 필수 항목으로 검사기에 넣는다.
5. **UI 배치 판단은 스크롤 위치(px)로 한다.** 이번 B안은 PC에서 보기 좋았지만 모바일에서 4,730px 지점이라 탈락했다. 눈짐작 대신 렌더링해서 좌표를 잰다.
