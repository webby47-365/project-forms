## 3. 제작 방식 변경 — 식별이슈와 결정

1. **파일럿 실패 (Haiku 가 표를 다시 짬)**: 통신판매업 신고서 1쪽 → 3쪽, 원문에 없는 소제목 삽입. 원문 텍스트만 보고 표를 재구성하면 법정서식 재현이 불가능하다고 판단.
2. **해결: 원문 PDF 선 격자 자동 변환** (사용자 승인: 원문 PDF 다운로드·다운로드 폴더 접근 허용, 2026-09-16)
   - 클라우드는 law.go.kr 직접 접속이 조직 정책으로 차단(403) → **내장 브라우저**로 페이지 열고 JS로 서식 목록·PDF 번호 조회
   - 브라우저 연속 다운로드는 첫 파일 이후 차단됨 → **PDF 32개를 한 파일(lawforms_batch1.bin)로 묶어 1회 다운로드** 후 클라우드에서 분리
3. **역할 분담 확정**: 표·문구 = 변환기(사람 손 안 댐) / 설명·FAQ·예시 = Haiku / 사실 검수·원문 대조 = Opus
4. **Opus 검수에서 고친 Haiku 오류 (사실성)**
   - 원문에 없는 수치 삭제: 식품영업 무신고 벌칙, 통신판매 변경신고 30일, 정보공개 처리기간 20일(원문은 "20일 경과 시 불복 가능")
   - 과장 수정: "미숙아 진단서 없으면 급여 못 받음" → 원문대로 "진단서 1부 첨부"
   - 틀린 예시값 교체: 개인사업자에 (주)상호, 금액 "1", 가명 "김테스트", 칸 제목·안내문에 넣은 예시 등 20여 건
5. **UI 변경 1건 (작음)**: 상세 화면 하단 고지 박스에 `법정서식 재현본 · 근거 법령·서식번호·개정일 + 원문 서식 링크`. 기존 `notice-box` 스타일 재사용(새 디자인 없음) — 비교 이미지 생략.

## 6. 개발 경험치 (SPEC_GUIDE 3-5절에 반영 완료)

1. **법정서식은 사람(에이전트)이 표를 다시 짜면 안 된다.** 원문 PDF 선 격자를 그대로 옮기고, 에이전트에게는 글(설명·FAQ·예시)만 맡긴다.
2. 한국 법정서식 PDF의 함정: **표 좌우 바깥 세로선이 없다**(가상 세로선 필요) · **글자 뒤 흰 바탕 사각형**이 표 선으로 잡힌다 · **좌우 나란한 표**를 따로 두면 위아래로 쌓여 쪽이 는다 · **표 안의 작은 표**는 바깥 칸과 겹쳐 글자가 사라진다.
3. Word/LibreOffice 표에서 **빈 칸의 문단 기호가 기본 글자(10.5pt) 높이를 차지**해 얇은 행이 2배로 부푼다 → 빈 칸은 1pt·줄간격 고정.
4. `tblGrid` 를 고치지 않으면 LibreOffice 가 열 폭을 무시한다(09-15 식별) → gov_table 은 격자를 직접 쓴다. 기존 grid/table 은 여전히 미교정(별건).
5. 원문 대조는 **순서 무관 지표**로 한다. 표를 옮기면 pdftotext 읽는 순서가 바뀌어 연속 문자열 비교는 오탐(55~90%)이 난다 → 줄 단위 2자 조각 개수 비교로 99~100%.
6. 빌드 검사 `출력물에서 'X' 항목을 찾을 수 없습니다` 경고가 **글자 소실을 실제로 잡았다**(인감신고서 서명란). 법정서식에서는 이 경고를 무시하지 말 것.
7. 내장 브라우저 자동 다운로드는 **연속 2번째부터 막힌다** → 여러 파일은 한 묶음(bin)으로 받는다.
8. 원격 저장소가 앞서 있으면 클라우드 작업본을 `git rebase origin/main` 후 차이 파일만 이관한다. catalog.json 은 병합 스크립트로 합친다(수작업 편집 금지 — 들여쓰기·count 가 틀어진다).
